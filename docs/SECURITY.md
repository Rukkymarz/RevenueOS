# Security & privacy baseline

- OIDC Authorization Code + PKCE with Keycloak; validate JWT signature, issuer and audience server-side. No hardcoded user passwords.
- `X-Business-Id` is not trusted; membership is checked for each request. PostgreSQL row-level policies on 16 tenant-owned tables require a transaction-local business ID and separate non-owner `revenueos_app` role. App connections **must not** use postgres/superuser or a role with BYPASSRLS. Business and membership tables are authenticated server-side and not under tenant RLS because `/me` must discover memberships before selecting a tenant.
- Explicit RBAC `admin > manager > operator > viewer`. Only managers/admins approve and transmit outbound messages. Approvals are recorded in durable tables. Approval UI retrieves and displays the exact target and message body before a manager decides. Action arguments are not derived from model output without validation.
- Resend: must have verified sender, documented contact basis, suppression/opt-out checks; send-once state is committed before provider API call. Ambiguous provider errors yield `unknown` rather than an automatic duplicate retry. Model drafts are never automatically sent.
- Quote import requires 32+ character HMAC secret and a signed body. Business ID is accepted for the transaction only after signature verification, and event IDs are deduplicated transactionally.
- Provider API keys remain server-side. Client-side local/session storage is used only for identity-session artifacts managed by OIDC library; never for provider secrets or lead exports. Static service-worker assets only; no offline caching of private data.
- No third-party executable plugins loaded at runtime. Connector registry is first-party only. External websites should be audited with allowlists, private-address/redirect rejection, and response caps before enabling unrestricted URL inputs.
- Default-deny metrics; `Content-Type` security, frame denial and cache-control headers on API. TLS, CSP, trusted reverse proxy, rate limiting, WAF, managed backup/restore and full centralized logging are **deployment responsibilities**.
- Data subject rights: implement identity-verified export, correction, deletion and retention scheduler before storing real EU/UK client personal data. This starter does not claim comprehensive GDPR/CCPA compliance. Email open tracking may be inaccurate and privacy-sensitive; do not treat it as consent.
- Additional hardening before exposure: configure Keycloak MFA enforcement, immutable release pins, image and Python/npm dependency scanning, secret rotation, allowlisted egress, backups and restore drills, rate limits per action, malware/attachment controls, and security review of reverse proxy, logs and retention.
